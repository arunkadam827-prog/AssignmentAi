Building REST APIs with Spring Boot: A Beginner's Practical Guide

November 17, 2026 12 min read JavaSpring BootREST API

Spring Boot makes it easier to create Java applications without spending time on repetitive configuration. In this guide, you will learn the main layers of a REST API and how a request travels through them.

1. What is a REST API?

A REST API allows applications to communicate over HTTP. A client sends a request to an endpoint, and the server returns a response, commonly in JSON format. For example, a student application might request GET /api/students to retrieve a list of students.

REST APIs commonly use standard HTTP methods: GET to read data, POST to create data, PUT or PATCH to update data, and DELETE to remove data.

2. Create a Spring Boot project

Start a project using Spring Initializr. Choose a supported Java version and add Spring Web. If the application needs database persistence, add Spring Data JPA and a database driver such as PostgreSQL or MySQL.

A simple package structure keeps responsibilities clear:

src/main/java/com/example/demo/
  controller/
  service/
  repository/
  entity/
  DemoApplication.java

The exact package names can vary, but separating these responsibilities makes the code easier to understand and maintain.

3. Understand the main application layers

Entity

An entity represents data stored in a database. With JPA, annotate the class using @Entity and identify its primary key with @Id.

@Entity
public class Student {
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;
    private String name;

    // getters and setters
}

Repository

A repository handles data access. Spring Data JPA can create common database operations from an interface:

public interface StudentRepository
        extends JpaRepository<Student, Long> {
}

Service

The service layer contains application logic. Keeping this logic outside the controller helps make endpoints smaller and easier to test.

@Service
public class StudentService {
    private final StudentRepository repository;

    public StudentService(StudentRepository repository) {
        this.repository = repository;
    }

    public List<Student> findAll() {
        return repository.findAll();
    }
}

Controller

The controller maps HTTP requests to application operations:

@RestController
@RequestMapping("/api/students")
public class StudentController {
    private final StudentService service;

    public StudentController(StudentService service) {
        this.service = service;
    }

    @GetMapping
    public List<Student> getStudents() {
        return service.findAll();
    }
}

4. Choose meaningful HTTP methods and endpoints

Design URLs around resources and use HTTP methods to describe the action. For a student resource, a typical API could include:

  • GET /api/students — return all students.
  • GET /api/students/5 — return the student with ID 5.
  • POST /api/students — create a student.
  • PUT /api/students/5 — replace or update a student.
  • DELETE /api/students/5 — delete a student.

Return appropriate status codes. For example, use 200 OK for a successful read, 201 Created after creating a resource, 204 No Content for a successful deletion with no response body, and 404 Not Found when a requested resource does not exist.

5. Add validation and handle errors

Never assume that incoming data is valid. Use Jakarta Bean Validation annotations such as @NotBlank, @Email, and @Size on request DTOs, then add @Valid to controller parameters. DTOs also help prevent clients from directly controlling internal entity fields.

For consistent error responses, handle exceptions centrally with @RestControllerAdvice and return clear messages with suitable HTTP status codes. Avoid exposing stack traces or secrets to API clients.

6. Test your API

Run the application and test endpoints using Postman, an HTTP client, or automated tests. Check successful requests as well as missing fields, invalid values, unknown IDs, and unauthorized requests where security is enabled.

For automated tests, use JUnit and Spring Boot testing support. Test service logic separately, and use web-layer tests to verify request mappings, validation, response bodies, and status codes.

7. Spring Boot REST API best practices

  • Use constructor injection instead of field injection.
  • Keep controllers focused on HTTP concerns; put business logic in services.
  • Use DTOs for request and response models when appropriate.
  • Validate input and return consistent error responses.
  • Keep database credentials and API keys in environment variables or a secret manager.
  • Document endpoints and test both normal and failure cases.
  • Use pagination for endpoints that may return large collections.

A good first project is a Student Management API with create, read, update, and delete operations. Once the basics work, add database migrations, authentication, pagination, and automated tests.

Key takeaways

A Spring Boot REST API is easier to maintain when each layer has a clear responsibility: controllers handle HTTP, services implement application logic, repositories access data, and entities represent persisted records. Build a small API, test each endpoint, and improve it step by step.
